## 1. 目的

### 1.1 なぜ自前で蓄積するのか

リーグは毎年 10 月中旬に全クラブの決算概要を PDF で公表し、メディアは売上や人件費のランキング記事を出す。数字そのものは手に入る。手に入らないのは次の 3 つである。

- **年度をまたいだ比較**: PDF は年度ごとに分かれていて、クラブ別の推移を並べるには毎回手で転記することになる。
- **速報値と確定値の区別**: クラブ単独の決算発表（例: 宇都宮の 2026 年 6 月期は 9 月に発表済み）はリーグ発表より 1 か月ほど早いが、「売上高」と「営業収入」のように定義がずれていることがある。両者を混ぜたまま並べると、比較が静かに壊れる。
- **一時要因の切り分け**: EASL 賞金や新アリーナ移転初年度の特需のような一時的な要因は、ランキング表には現れない。

### 1.2 答えたい問い

データ構造は、次の問いに答えられる形で設計する。問いに使わない項目は集めない。

| # | 問い | 必要なデータ |
| - | --- | --- |
| Q1 | 上位と下位の売上格差は広がっているか。B.PREMIER 基準（売上 12 億円）との距離はどうか | 営業収入（全クラブ・複数年） |
| Q2 | クラブの稼ぎ方はどう分かれるか（チケット型 / スポンサー型 / 物販型） | 営業収入の内訳 |
| Q3 | 人件費をかけたクラブは勝ち、利益も残しているか | トップチーム人件費、勝率、営業利益 |
| Q4 | 伸びのうち、一時要因を除いた実力ベースの成長はどれだけか | 一時要因（賞金・特需）とその金額 |

Q3 と Q4 はメディアのランキング記事では答えが出ない問いで、このデータベースを作る理由そのものである。

### 1.3 対象範囲

- **クラブ**: 2026-27 シーズンに B.PREMIER に所属するクラブ（D1）。所属の判定はクラブ単位で行い、シーズンごとのディビジョンでは行わない。たとえば B2 から昇格して B.PREMIER 入りしたクラブも、B2 時代の決算を含めて対象にする。
- **期間**: B.LEAGUE 開幕の 2016-17 シーズンから最新シーズンまで（D2）。それより前の bj リーグ・NBL 時代は扱わない。

この範囲には**生存者バイアス**がある。B.PREMIER に入れたクラブの過去だけを見ているので、「開幕から売上が伸び続けた」という傾向は、伸びたクラブだけを選んだ結果として出てきてしまう。Q1（格差）を論じる記事では、比較対象として B.PREMIER 外のクラブを、少なくとも最新シーズンのリーグ全体平均と並べること。範囲を広げるかどうかは、最初の Q1 記事を書く時点で再判断する。最初の記事（[task-005](../tasks/phase-07/task-005-first-article.md)）は Q4 から入る。

### 1.4 ノンゴール

- 決算書（貸借対照表・損益計算書）の全科目を再現すること。問いに必要な科目だけを持つ。
- 記事本文の転載。保存するのは数値（事実）と出典 URL だけにする（[research-guide.md §6](research-guide.md#6-著作権と引用)）。
- 自動クローリング。各クラブのサイト構成はばらばらで、保守コストに見合わない。取り込みは人が記事を選び、Claude Code のコマンドで構造化する半自動方式にする。

## 2. 全体像

```
 [調査]                     [整理]                          [蓄積]                       [発信]
 リーグ決算概要 PDF ─┐
 クラブ決算リリース ─┼─→ /add-club-finance ──→ src/content/club-finances/*.json ──→ /data/bleague-finance/ （常設の比較ページ）
 報道記事 ───────────┘    （抽出・単位変換・      （Zod で検証。build で落ちる）     /blog/<slug>/        （分析記事。図を埋め込む）
                           出典付与）
 import/club-finances.md ─→ /bulk-import （リーグ PDF の一括転記用）
```

- **単一の真実**は `src/content/club-finances/` の JSON とする。可視化もブログも、ここから build 時に読む。
- 図は build 時に SVG として生成し、クライアント JS のチャートライブラリは使わない。実装規約の「third-party script ゼロ」「初期 JS < 50KB」を守るためである（[task-004](../tasks/phase-07/task-004-finance-visualization.md)）。

## 3. フェーズ

| Phase | 時期の目安 | ゴール | タスク |
| --- | --- | --- | --- |
| 7-A | 〜2026-10 中旬 | ブログ基盤とデータスキーマを用意し、発表済みのクラブ（宇都宮ほか）と 2024-25 上位を速報値として入れる | task-001, 002, 003 |
| 7-B | リーグ発表（2026-10 中旬見込み）直後 | 2023-24〜2025-26 の対象クラブ全件を確定値で揃える（2023-24 の決算概要は公開済み） | task-003（一括取り込み） |
| 7-C | 7-B の後 | 比較ページと最初の分析記事を公開 | task-004, 005 |
| 7-D | 7-C と並行、新しい年度から順に | 2016-17〜2022-23 をさかのぼって取り込む | task-006 |

さかのぼり（7-D）を最後に回すのは、古い年度ほどリーグ資料の科目体系が今と違う可能性が高いからである。新しい年度でスキーマを固めてから、古い資料の差分を吸収する。

7-A でスキーマを作り込みすぎないこと。リーグ PDF の科目体系を見てから内訳項目を確定させる（[data-model.md §5](data-model.md#5-未確定事項)）。7-A の役割は器を用意し、速報値で一度流してみることである。

## 5. 作業環境の制約

Claude Code on the web の環境では、ネットワーク設定によって `www.bleague.jp` や各クラブの公式サイトへのアクセスがブロックされることがある。対処は次のどちらか。

1. 環境の Network access 設定で、該当ドメインを許可リストに追加する。
2. 記事本文やリーグ PDF の表を、人がコピーしてコマンドに貼り付ける（`/add-club-finance` はテキスト入力を受け付ける設計にする）。
