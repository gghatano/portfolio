# 調査・整理ガイド

決算記事から数値を拾い、[data-model.md](data-model.md) の形に整えるまでの手順。人が作業するときも、`/add-club-finance` コマンドを実装するときも、本書に従う。

---

## 1. ソースの優先順位（tier）

同じ項目について複数のソースが異なる値を出していたら、tier の高いほうを採用する。

| tier | 値 | ソース | 特徴 |
| - | --- | --- | --- |
| 1 | `league` | リーグ公式「クラブ決算概要」（例年 10 月中旬、bleague.jp に PDF） | 全クラブで科目と年度の定義が揃っている。**確定値**はこれだけ |
| 2 | `club` | クラブ・運営会社の決算リリース、IR 資料 | リーグ発表より早いことが多い。科目名・連結範囲がクラブごとに違う |
| 3 | `press` | 新聞・専門メディアの報道（日経、地方紙、バスケットボールキング等） | クラブ発表の要約。丸め（「約 12 億円」）が入る |
| 4 | `secondary` | note などの個人分析、まとめサイト | 単独では採用しない。tier 1〜3 へたどるための手がかりに使う |

- tier 4 だけを根拠にした数値は保存しない。
- 2 件以上の press が一致していても、tier が上がるわけではない。
- 検索エンジンや AI 要約が返した数値は、元記事で確認できるまでソースとして扱わない。単位の取り違え（「51.7 億円」を「51.7 billion」とする等）が実際に起きている。

## 2. 発表カレンダー

| 時期 | 出るもの | 対応 |
| --- | --- | --- |
| 8〜9 月 | 6 月決算クラブの単独発表（宇都宮、千葉J など） | 速報値（`status: preliminary`）として登録 |
| 10 月中旬 | リーグ「クラブ決算概要」（B1・B2 全クラブ） | 確定値として一括登録。速報値は上書きし、`sources` に tier 1 を追加 |
| 随時 | 報道、クラブの事業報告 | 一時要因（`one_off_items`）や内訳の補完に使う |

6 月以外に決算期を置くクラブ（親会社の会計年度に合わせている場合など）は、リーグ発表を待つほうが早くて確実なことが多い。

## 3. 抽出の手順

1. **クラブとシーズンを特定する。** 記事の「2026 年 6 月期」「第 16 期」「2025-26 シーズン」などの表記から `season`（`2025-26` 形式）を決める。決算期の対応は [data-model.md §3](data-model.md#3-シーズンと決算期の対応) を参照。
2. **数値を拾う。** 記事中に数字で書かれている値だけを拾う。前年比から逆算した値や、割合から計算した値は保存しない（計算は可視化側でやる）。
3. **単位を千円に揃える**（§4）。
4. **科目を対応づける**（§5）。記事の科目名が data-model の項目と一致しない場合は、無理に当てはめず `notes` に残す。
5. **出典を付ける。** URL、タイトル、公開日、tier、その出典から取った項目名を `sources` に記録する。
6. **一時要因を拾う。** 「EASL 優勝賞金」「アリーナ移転初年度」のように、記事が増減の理由として挙げている一時的な要因を `one_off_items` に記録する。金額が書かれていなければ金額は空にし、ラベルと説明だけを残す。
7. **検証する。** `pnpm build` を通す（内訳の合計と総額の整合はスキーマで検証される）。

---

## 4. 単位と精度

- 保存単位は**千円の整数**とする。リーグ PDF が千円単位で、Bリーグの比較記事もこれに合わせていることが多い。
- 元資料の精度を `resolution`（千円単位の刻み幅）に記録する。精度が粗い値どうしの合計チェックで誤差を許容するためである。千円単位以上の精度なら省略してよい。

| 元の表記 | 保存値（千円） | `resolution` |
| --- | --- | --- |
| 4,035,787,153 円 | 4035787 | 省略（1） |
| 5,171,817 千円 | 5171817 | 省略（1） |
| 2 億 698 万円 | 206980 | 10 |
| 3,567 百万円 | 3567000 | 1000 |
| 51.7 億円 | 5170000 | 10000 |
| 約 12 億円 | 1200000 | 100000 |

- 「約」「超」「過去最高の 40 億円」のような丸めた表現しかない場合は、そのまま書かれた数値を入れ、`resolution` を粗く記録する。「40 億円超」は 4000000 とし、`notes` に「超」の表記であることを残す。
- 円単位の値は千円未満を切り捨てる（リーグ PDF の慣例に合わせる。差が出たら tier 1 の値で上書きされる）。

## 5. 科目の対応づけ

クラブ発表と報道では、同じ概念が別の名前で呼ばれる。

| 記事上の表記 | data-model の項目 | 注意 |
| --- | --- | --- |
| 営業収入、売上高、売上 | `revenue.total` | **クラブ単独発表の「売上高」は、リーグの「営業収入」と一致しない場合がある**（連結範囲、スクール事業や別会社の扱い）。tier 1 が来るまでは `status: preliminary` |
| スポンサー収入、広告料収入、パートナー収入 | `revenue.sponsorship` | |
| 入場料収入、チケット収入 | `revenue.ticket` | |
| 配分金、リーグ配分金 | `revenue.distribution` | |
| 物販収入、グッズ収入、MD 収入 | `revenue.merchandise` | |
| アカデミー関連収入、スクール収入 | `revenue.academy` | |
| 賞金 | `revenue.other` ＋ `one_off_items` | 金額が分かれば両方に記録する |
| トップチーム人件費、選手・スタッフ人件費 | `expenses.top_team_personnel` | 「人件費」とだけ書かれている場合はフロント職員を含む可能性がある。対応づけずに `notes` に残す |
| 営業利益 | `operating_income` | |
| 経常利益 | `ordinary_income` | |
| 当期純利益、最終利益、純利益 | `net_income` | 「税引前当期純利益」は別物。`notes` に残す |
| 純資産 | `net_assets` | 債務超過はマイナス値で表す |

リーグ PDF の正式な科目体系は task-002 で確認し、本表と data-model を更新する。

## 6. 著作権と引用

- 保存するのは**数値（事実）と出典情報だけ**にする。記事本文や表をそのまま貼り込まない。
- `notes` や `one_off_items` の説明は自分の言葉で要約する。どうしても引用する場合は、20〜30 字程度にとどめてかぎ括弧で囲み、出典を付ける。
- ブログ記事で図や表を出すときは、出典（リーグ発表、各クラブ発表）を図の下に必ず明記する。

---

## 7. 矛盾が見つかったとき

1. tier が違う → 上位を採用し、下位の値は捨てる（`sources` には両方残してよい）。
2. tier が同じで値が違う → 公開日が新しいほうを採用し、`notes` に食い違いを記録する。
3. tier 1 と tier 2 で「営業収入」と「売上高」が食い違う → 定義の違いとして扱い、tier 1 を採用する。差額が大きい（5% 超）ときは、ブログで触れる価値のある材料として `notes` に記録する。
