## ステータス
- 未着手

## 背景
対象期間は B.LEAGUE 開幕の 2016-17 シーズンからとした（[設計書 D2](../../bleague-finance/README.md#41-決定済み2026-10-03)）。task-002 と task-003 で直近 2 年分の器と取り込み経路ができたら、残りの 2016-17〜2022-23（7 シーズン）を対象クラブ全件ぶん取り込む。件数はおよそ 26 クラブ × 7 シーズン ＝ 約 180 件になる。

件数より厄介なのは、資料の形式が年度によって違うことである。開幕当初の決算概要と今の決算概要では、開示している科目や区分が同じとは限らない。形式の違いを確かめずに流し込むと、「スポンサー収入」の中身が年度ごとに違う時系列が、見た目だけ揃って出来上がってしまう。

## 受け入れ基準
- [ ] **取り込む前に**、各年度のリーグ決算概要を 1 本ずつ確認し、科目体系の差分表を `docs/bleague-finance/league-report-formats.md` にまとめる。年度、開示科目、data-model の項目への対応、対応できない科目の扱いを書く
- [ ] 差分表を見て、data-model の変更が必要なら先に変更する（科目の追加、`notes` で吸収するルールの明文化など）
- [ ] 新しい年度から順に取り込む（2022-23 → 2016-17）。1 シーズンごとに 1 コミットにする
- [ ] 各年度で、対象クラブの所属ディビジョンを確認して `division` を入れる
- [ ] リーグ決算概要に載っていないクラブ・年度（下位カテゴリ所属だった年など）は、クラブ発表や報道を探す。見つからなければ欠損のままにして、`league-report-formats.md` の欠損一覧に理由とともに記録する
- [ ] 12 か月でない変則決算の期を `notes` に記録する（data-model §3）
- [ ] チーム名・運営会社名の変遷を `clubs.aliases` に反映する
- [ ] `scripts/finance-coverage.mjs` の出力で、全クラブ × 全シーズンが「確定値 / 速報値 / 欠損（理由記録済み）」のいずれかになっている
- [ ] lint / check / build が 0 errors

## 設計判断
- **形式の確認を取り込みより先にやる。** 年度をまたいだ比較の正しさは、科目の対応づけで決まる。対応づけを決めずに数値だけを先に入れると、後から全件を直すことになる。
- **新しい年度から取り込む。** 今の形式に近い年度から順に進めれば、形式の差分が 1 年ずつしか増えない。
- **欠損は欠損として残す。** 埋まらない年度を推定値で埋めない。欠損があること自体が、そのクラブの歴史（下位カテゴリ時代、運営会社の交代）を表している。
